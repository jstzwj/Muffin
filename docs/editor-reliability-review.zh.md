# 基础编辑可靠性修复（2026-11-01）

本轮针对代码审查与复现确认的问题，修复文档历史、保存、草稿、文档内搜索和文件操作入口。

## 文档历史与保存

- `DocumentSession` 持有唯一 `UndoStack`。实时编辑与源码编辑使用同一份事务历史、同一个执行器实现。
- 实时编辑保留现有结构化事务；源码事务记录精确的 UTF-16 文本差异以及编辑前后的选区，支持没有可编辑 AST 节点的语法和空文档。
- 文本差异重放前校验被替换的内容。应用失败会归还撤销步骤，不会消耗历史。
- 历史使用独立状态编号记录保存点。新编辑不能跨保存点合并；撤销和重做成功后才同步修改标记。
- 文件写入成功后，保存规范化通过文档编辑更新文本并记录历史。补末尾换行不会重新加载逻辑文档，也不会丢弃此前的历史。
- 切换视图同步源码选区；源码撤销保留阅读位置。

## 草稿格式

新快照为 `<key>.draft`，通过一次 `QSaveFile` 提交：

1. 固定首行 `MUFFIN-DRAFT 1`。
2. 单行 JSON 元数据，包含来源、时间、字符数及正文 UTF-8 字节数。
3. 原始 UTF-8 正文。

读取时校验头部和正文长度。只有新快照提交成功后才移除旧的 `.md/.meta` 文件。旧格式仍可恢复；没有元数据的 `.md` 作为未命名草稿提供恢复。清理只删除没有正文的旧元数据，不删除孤立正文。

## 文档内查找与替换

- 普通文本搜索对不可变的 PieceTable 快照流式匹配；正则使用具备取消回调、时间和资源预算的 PCRE2。
- 保留最多 10,000 条位置缓存，同时统计完整匹配数量。缓存外的目标在扫描时选择，结果上限不会限制可导航范围。
- 查找及替换结果计算在后台执行。小结果集的连续导航直接复用缓存。
- 替换顺序拼接未修改片段与替换内容，不逐条移动不断增长的文档尾部。
- 关闭、移动标签页、修改文档或发起新请求会使旧任务取消或失效。回到界面线程后仍检查文档版本；过期替换不得写入。
- 提交替换时仍需要在界面线程更新文档和布局。后台匹配不代表超大文档的最终解析完全没有耗时。

## 入口一致性

- Markdown 拖入的“导入”创建独立、未保存的副本，保留文件大小与扩展名检查；“打开”沿用标签页复用行为。
- 其他可导入文件复用菜单的 Pandoc 导入流程及错误提示。
- Ctrl+P 的普通编辑键保留过滤防抖，仅方向导航和确认打开需要立即刷新待处理结果。

## 回归覆盖

- 两种模式交替编辑、撤销和重做；反向选区；保存点前后历史。
- 保存补换行后继续输入；写入失败保留保存点和重做历史；锁定已有修改的文档后保存；源码长段落撤销后的阅读位置。
- 旧草稿正文缺少元数据、迁移失败、快照截断、空文档恢复。
- 十万次替换、数百万命中、缓存外定位、零宽匹配、超大捕获组编号和正则资源预算。
- 后台替换期间继续编辑、替换后撤销、长表格与代码块搜索定位。
- Markdown 拖入偏好和 Ctrl+P 编辑键的防抖。
