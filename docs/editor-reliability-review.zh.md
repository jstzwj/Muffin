# 基础编辑可靠性修复（2026-11-01）

本轮针对代码审查与复现确认的问题，修复文档历史、保存、草稿、文档内搜索和文件操作入口。

## 文档历史与保存

- `DocumentSession` 持有唯一 `UndoStack`。实时编辑与源码编辑使用同一份事务历史、同一个执行器实现。
- 实时编辑保留现有结构化事务；源码事务记录精确的 UTF-16 文本差异以及编辑前后的选区，支持没有可编辑 AST 节点的语法和空文档。
- 文本差异重放前校验被替换的内容。应用失败会归还撤销步骤，不会消耗历史。
- 历史使用独立状态编号记录保存点。新编辑不能跨保存点合并；撤销和重做成功后才同步修改标记。
- 文件写入成功后，保存规范化通过文档编辑更新文本并记录历史。补末尾换行不会重新加载逻辑文档，也不会丢弃此前的历史。
- 切换视图同步源码选区；源码撤销保留阅读位置。

## 草稿格式

新快照为 `<key>.draft`，通过一次 `QSaveFile` 提交：

1. 固定首行 `MUFFIN-DRAFT 1`。
2. 单行 JSON 元数据，包含来源、时间、字符数及正文 UTF-8 字节数。
3. 原始 UTF-8 正文。

读取时校验头部和正文长度。只有新快照提交成功后才移除旧的 `.md/.meta` 文件。旧格式仍可恢复；没有元数据的 `.md` 作为未命名草稿提供恢复。清理只删除没有正文的旧元数据，不删除孤立正文。

## 文档内查找与替换

- 普通文本搜索对不可变的 PieceTable 快照流式匹配；正则使用具备取消回调、时间和资源预算的 PCRE2。
- 保留最多 10,000 条位置缓存，同时统计完整匹配数量。缓存外的目标在扫描时选择，结果上限不会限制可导航范围。
- 查找及替换结果计算在后台执行。小结果集的连续导航直接复用缓存。
- 替换顺序拼接未修改片段与替换内容，不逐条移动不断增长的文档尾部。
- 关闭、移动标签页、修改文档或发起新请求会使旧任务取消或失效。回到界面线程后仍检查文档版本；过期替换不得写入。
- 批量替换、撤销和重做共用 `DocumentSession` 的后台准备与提交管线。后台构造文本、AST、节点索引、源码位置索引和大纲；界面线程交换完整状态，统一提交撤销记录与修改标记。准备期间继续输入、重新加载、修改解析设置或锁定文档，会使旧任务失效。
- 历史只保存不可变文本及选区、阅读位置，不保存整份 AST。回放就绪前不移动历史指针；准备期间暂停新的撤销/重做，普通输入仍可取消待处理任务。历史按 100 条和 256 MiB 文本保留预算裁剪；共享缓冲按保守上界计费，最近一条超大操作仍保留，以便撤销。
- 原生布局使用可暂停的 C++20 协程，同步布局与界面分片布局执行同一算法。HTML 容器拓扑、CSS 计数器、顶层估算及位置索引可以分片运行。界面按约 4 ms 的工作预算调度，保持消息循环可运行；未完成布局不参与绘制和命中测试，完成后恢复阅读锚点。新主题、窗口尺寸或文档版本会取代旧任务。
- 大纲的层级与源码位置随完整状态在后台解析，界面读取共享完成结果；局部编辑后按文档版本失效。纯 AST/索引的旧状态在后台释放；旧布局中的 Qt 绘制资源在界面线程分批释放，剩余纯索引也在后台回收，避免最后一次析构重新造成停顿。隐藏标签页稍后激活时也使用分片布局，避免把延迟移到切换标签页时。
- 小范围、无跨块依赖的替换复用普通编辑的局部解析与拼接逻辑，保留其他节点；变化窗口上限 32 Ki 字符，带上下文的解析窗口上限 64 Ki 字符、16 个顶层块。引用、HTML 边界、跨行或分散的大范围改动回退完整后台解析。单段连续的 PieceTable 缓冲在请求完整字符串时直接共享，减少重复复制。

### 性能契约与边界

分片预算是调度目标，不是实时系统的硬上限：单次 Qt 字形布局、一个复杂块的测量及 Flex/Grid 全局约束求解仍不可中途抢占。cmark 的单次解析也不可抢占，但在后台执行；取消后不发布结果。当前局部优化覆盖有明确上下文边界的小范围修改，尚未把相距很远的多处变化合成多个独立增量窗口。大文档的全量解析总量与临时新旧状态的峰值内存仍然存在，不能把“消息循环可响应”解释为“没有计算成本”。

专项验收同时检查事件循环心跳、源码映射与完整解析的一致性、分片和同步布局的几何/CSS 计数器一致性、反向选区、保存点、取消、关闭、重入观察者以及布局期间的主题/窗口/文档切换。

### 大文档专项测量

`MuffinBatchEditTest` 使用标题、中文段落、粗体和链接构成的文档，执行批量替换提交、撤销、重做、输入取消、锁定取消与关闭会话。5 ms 定时器记录事件循环间隔，使用惰性原生布局。目标 PieceTable 预先准备，模拟真实搜索后台任务的交接；下表“提交至布局完成”包含后台解析、索引构造、状态提交和布局，不包含匹配与生成替换文本的时间。

## 入口一致性

- Markdown 拖入的“导入”创建独立、未保存的副本，保留文件大小与扩展名检查；“打开”沿用标签页复用行为。
- 其他可导入文件复用菜单的 Pandoc 导入流程及错误提示。
- Ctrl+P 的普通编辑键保留过滤防抖，仅方向导航和确认打开需要立即刷新待处理结果。

## 批量编辑改造复审

复审发现并修正了以下五个边界问题：

1. 源码模式切回实时编辑时遗漏了批量刷新标记，会退回同步全量布局。各个标签页、视图切换和导航入口现在共用 `DocumentTab::ensureRenderViewCurrent()`，统一消费延迟刷新状态。
2. 保存的 HTML 源码编辑状态在分片布局完成前无法命中对应块，原先会提前消费恢复请求。现在保留完整请求，等待 `layoutReady` 后恢复光标、阅读位置和编辑模式。
3. CSS 计数器在首次挂起时就被标记为当前版本的完整缓存。取消后使用同一主题重试会误用半成品；现在只在计算完成后发布缓存版本。
4. 性能统计的线程局部栈作用域跨越协程挂起点，多个视图交错运行或取消时可能破坏嵌套关系。现在统计作用域只覆盖每次恢复执行的区间，不跨越事件循环。
5. 完整 AST 替换后，代码/HTML/公式等源码块编辑器仍可能按旧的同类块序号寻找目标；前面新增或删除同类块时，后续输入会选错块。现在在发布选区前，依据映射后的光标重新绑定活动编辑器，不沿用旧序号，也不把旧的临时换行写入新块。此过程只通过节点 ID 查询，不在界面线程重新扫描整份文档。

新增回归覆盖取消计数器后重试、两个布局任务交错与取消、源码模式切回的异步布局、延迟 HTML 编辑状态恢复，以及“新增代码块的批量替换 → 输入 → 撤销输入 → 撤销替换 → 再输入”。

架构判断：不可变准备状态、版本校验、原子提交和统一历史回放解决了批量操作的线程边界与一致性问题；同步与分片布局共用一个实现，避免维护两套排版语义。局部解析继续沿用原有拼接规则，不能安全确定边界时回退完整解析。这属于对文档状态和调度生命周期的重构，不依赖固定延时或嵌套事件循环。上文列出的单块不可抢占成本、全量计算及峰值内存仍是明确边界。

### 分屏预览的阅读位置与容器布局

阅读位置的源码映射由 `DocumentSession` 在成功提交文本变更后统一发布，覆盖源码输入、文档命令、撤销、重做和批量替换。替换操作保留各处修改的原始范围，避免把两个匹配之间未变化的阅读位置误判为替换内容。完整文本回退通过公共前后缀映射；它不等同于任意文本重排的语义匹配。取消或失效的后台任务不发布位置变更。

预览保存源码偏移和文字行的屏幕位置，不保留旧 AST 指针。新布局发布时，使用与编辑导航相同的源码解析器重新解析阅读锚点。文档命令恢复光标时不自动移动预览；开启同步滚动后，由标签页显式同步。关闭同步时，批量操作也不将源码面板的位置覆盖到预览。

HTML 容器无法局部拼接时，直接进入可取消的布局管线。容器估算和普通流式容器的子块构建可以分片；发布前先准备阅读位置及可见区域，避免发布后再同步构建整棵容器。新旧布局共用容器排版与生成内容的收尾逻辑。图片、字体等资源更新需要重建 HTML 流时，也走相同管线。取消中的容器由未发布布局持有，已完成的子块在界面线程逐叶分批释放。

这些调整没有消除单块字形布局、复杂 Flex/Grid 求解及全量解析的成本。分片的目标是让连续输入能取消旧布局并保持消息循环运行，不能承诺所有文档都在固定毫秒内完成一片。

分隔条调整宽度时，源码视图保留阅读锚点，不再调用“让光标可见”而跳向屏幕外的光标。重算换行高度期间的临时滚动条位置不参与两栏同步；预览宽度改变也使用可取消的布局与阅读锚点恢复流程。

写作模式由标签页依据实际编辑视图分配。分屏时，专注淡化和打字机光标跟随只作用于源码；只读预览不保留打字机留白，不运行旧渲染光标的居中动画，也不根据旧选区淡化正文。源码光标跟随使用换行后的实际光标几何位置，兼容始终居中与舒适区域两种偏好，不再由主窗口在光标通知中重复滚动。模式选择保持不变，切回所见即所得后恢复渲染区的写作效果。

居中目标计算前，只测量光标前方可能进入视口的源码行，避免估算高度在绘制时再推移光标。光标行在文档坐标中取整，再减滚动偏移；行中心采用对正负坐标一致的计算，避免屏幕外的负坐标进入视口时产生 1 像素重复滚动。

预览栏的布局菜单支持左右分栏、上下分栏及交换源码和预览。切换时保留各栏阅读锚点、源码选区和各栏所占比例；方向、顺序、比例和同步滚动状态随标签页保存并参与会话恢复。回归覆盖普通 Markdown、HTML 混排、同步与独立滚动、屏幕外的反向选区，以及连续调整宽度后切换方向、交换位置、恢复会话。
