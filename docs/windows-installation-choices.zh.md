# Windows 安装选项的保存与升级

安装界面的“右键菜单”和“打开方式”是独立的可选集成。注册为“打开方式”候选程序不表示设为默认程序，也不会在第一次启动时弹出默认编辑器询问。需要改变默认程序时，使用“偏好设置 → 文件 → 设为默认…”打开 Windows 默认应用设置，由用户确认。

## 状态来源

安装程序和应用共用 `HKCU\Software\Muffin\Muffin\integration` 下的两个 DWORD：

| 名称 | 值 | 含义 |
| --- | --- | --- |
| `contextMenu` | `0` / `1` | 禁用 / 启用资源管理器右键入口 |
| `openWith` | `0` / `1` | 禁用 / 启用 Markdown 的“打开方式”候选项 |

缺少记录与明确的 `0` 不同。安装程序首先读取有效的选择记录；记录缺失或格式不合法时，如果已检测到旧 MSI、旧安装包或现有集成，则参考当前注册项。已有安装的缺失注册项表示关闭；只有全新安装才使用两个选项默认开启的初始值。

应用内的开关会同时修改实际注册项及这两个值。自定义安装界面与裸 MSI 使用相同的默认选择规则。升级时不迁移已经过时的 MSI 功能选择，避免覆盖用户后来在应用内修改的选项；用户在本次安装界面或通过 `ADDLOCAL` / `REMOVE` 明确指定的功能仍然优先。

## 保存时机

自定义安装界面检测状态时只读取。MSI 在功能选择确定后计算两个值，由主功能的注册表组件写入。写入属于 Windows Installer 事务，取消或失败时随安装回滚，不在安装界面检测、关闭或失败回调中单独保存。

安装成功时，即使两个功能均未选择，也会写入两个 `0`。卸载会移除安装器拥有的集成与选择记录，其他应用偏好和用户笔记不受影响。

## 自动验证

- `MuffinWindowsIntegrationTest` 将测试进程的 HKCU 重定向到独立临时注册表树，使用实际 C++ 注册表写入逻辑验证四种组合、再次取消及 DWORD 格式，不修改用户的真实文件关联。
- `MuffinInstallerOptionsTest` 在独立注册表树中验证首次安装、旧安装、便携版集成、显式取消及损坏记录回退，并检查检测过程不创建状态。
- 对构建好的 MSI 运行 `build/installer-options-test/IntegrationOptionsTest.exe <MSI路径>`：只打开包并计算条件，不执行安装；使用 Windows Installer 的条件求值器验证 128 种组合与安装界面一致，并检查最终选择的事务写入格式。

## 安装验收

在 Windows 虚拟机中使用独立测试版本，分别安装四种选项组合，再升级到新版本；检查界面预选项、实际注册项和两项 DWORD。随后在应用偏好中更改选项，再升级确认继承。还应覆盖裸 MSI、静默安装、安装中取消或失败回滚，以及新安装后直接进入编辑器且不出现默认编辑器询问。

这些完整安装步骤与只读包验证不同，需要在隔离环境中完成，不能用条件求值测试代替。
