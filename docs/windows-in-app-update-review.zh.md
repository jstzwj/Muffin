# Windows 应用内更新：代码审查记录

审查日期：2026-10-30。

本轮按要求仅走读代码并修正发现的问题，没有运行构建、测试、签名脚本或实际安装升级。下述内容是实现契约及静态审查结论，不代表已完成端到端验证。

## 范围与流程

Windows 安装版使用应用内下载和重启更新；Windows 便携版、Linux 和 macOS 保持原有发布页下载入口。

1. GitHub Releases 返回新版本，按当前应用架构选择 Windows x64 或 ARM64 安装包与更新清单。
2. 使用内置 ECDSA P-256 公钥验证清单签名，再流式下载并验证安装包大小与 SHA-256。
3. 用户选择“重启并更新”，更新器检查其他进程，锁定安装包，逐个检查窗口中的未保存内容。取消保存时保持窗口打开。
4. 保存各窗口的标签页、选区、阅读位置和目录状态。安装程序确认已就绪后，编辑器以排他创建方式写入 `update.ready.decision`，批准安装并退出。
5. 安装程序同时要求明确批准和原进程退出，才开始 MSI 安装。取消与批准使用同一个决策文件仲裁；普通退出或崩溃不能代替批准。
6. MSI 在事务内移除旧产品；失败时由 Windows Installer 执行回滚。安装程序完成后以原用户权限重新启动应用。
7. 应用恢复窗口，并初始化文件打开分发器；后续从资源管理器打开文件仍走正常路径。

## 本轮修正

| 问题 | 处理 |
| --- | --- |
| 恢复更新会话的启动分支没有启用文件打开分发器 | 返回恢复的主窗口，并调用正常分发器初始化入口 |
| 保存对话框的嵌套事件循环允许重复触发重启、改变窗口集合 | 在首个保存提示前进入准备状态，阻止重复操作和未经批准的窗口关闭 |
| 更新期间收到打开文件请求可能改变已确认的会话，或在退出时丢失 | 进程间请求在确认接收前就能中止更新；已确认但仍在排队的请求同样优先于重启 |
| 准备完成的窗口仍可能自动保存或弹出外部文件重载提示 | 增加窗口准备状态；中止更新时恢复自动保存和延后的提示 |
| 仅等待父进程退出，可能将崩溃或交接超时误当成安装许可 | 增加排他决策文件；取消优先阻止后续批准，已批准后的取消等待退出后重新打开应用 |
| 安装程序在交接失败、检测失败或检测到更新版本时可能停留不退出 | 区分用户关闭与已完成操作的关闭，补齐非交互模式退出码及退出路径 |
| MSI 默认在事务之前移除旧产品 | 显式使用 `afterInstallInitialize`，让旧产品移除参与事务回滚 |
| 更新对话框依赖原窗口，偏好设置的模态循环还会阻挡写作 | 更新器拥有独立对话框；从偏好设置进入更新时结束偏好设置的模态循环 |
| 下载结束时未统一处理最后的缓冲区数据 | 最后一次读取仍经过相同的限额、写入及哈希处理 |
| 安装包校验后到执行前仍可被改写 | Windows 文件句柄只允许共享读取，覆盖校验、保存提示和启动交接阶段 |
| 更新安装包可能长期残留在临时目录 | 记录自己的下载目录；只清理已结束任务的已知文件，不递归删除未知内容 |
| 公钥变化未触发增量 CMake 配置，密钥初始化失败后不能重试 | 跟踪公钥输入并检查格式；初始化脚本重用匹配的本地密钥，拒绝静默更换信任根 |

## 回归约束

现有安装程序回归代码已加入“无批准不安装”“取消与批准冲突”和 MSI 移除顺序的断言。本轮未执行这些断言。

后续有合适条件时，仍需确认 Windows 的文件共享、Burn 启动与提升权限、拒绝 UAC、真实 MSI 回滚及多窗口恢复表现。代码审查不能代替这些运行结果。

## 发布约束

发布工作流使用 `MUFFIN_UPDATE_SIGNING_KEY` 签署更新清单，公钥固定在 `resources/update-public-key.txt`。签名密钥必须与内置公钥一致；缺少密钥或不匹配时拒绝发布可供应用内安装的更新。

本轮没有创建、更换或上传密钥，也没有提交、推送或发布版本。以后更换公钥应设计兼容迁移，不能直接替换现有用户信任的密钥。
